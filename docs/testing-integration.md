# Тестирование: серверный сценарий WordPress

## Действующее правило — 25 октября 2026

По прямому уточнению пользователя 25 из 50 правильных ответов (ровно 50%) достаточно для допуска к эссе. После успешного завершения попытки доступных повторных попыток в этом сезоне становится 0; сервер отклоняет новый запрос старта с `test_already_passed`. Повтор запроса с прежним ключом остаётся идемпотентным и не создаёт попытку. Интерфейс автоматически переходит на страницу эссе после получения успешного результата, включая восстановление состояния после перезагрузки. Числовая оценка участнику не раскрывается. Настройки открытия приёма эссе действуют отдельно.

При 24/50 и ниже можно повторить тест в пределах трёх попыток. В другом сезоне лимит независимый. Описания ниже о разрешённой пересдаче после успеха относятся к предыдущей версии и этим правилом заменены.

## Новое уточнение заказчика — 18 октября

Заказчик сообщил: «мы ему не показываем его балл если более 50 то идем дальше на эссе».

Подтверждённое изменение требований: участнику не показывать числовой балл и процент результата; успешный тест ведёт к эссе. Баллы продолжают вычисляться и храниться на сервере для общей таблицы организаторов. Это уточнение имеет приоритет над прежними макетами с процентным кольцом и видимыми баллами.

Реализовано 18 октября по поручению пользователя: из WordPress-шаблона и статического макета убраны баллы, процентное кольцо и числовые примеры результата. Участник видит «Тест пройден» / «Тест не пройден». При успехе экран показывает следующий этап — эссе, без предложения пересдачи; при неуспехе остаётся пересдача при наличии попыток. Сдача эссе пока не реализована, поэтому кнопка перехода пока недоступна и это явно написано на экране. В конфигурации предусмотрен `essayUrl` для защищённой страницы следующего этапа.

Публичная функция `tarhan_public_attempt()` возвращает только разрешённые поля, включая `passed`, без `score` и `percent`. Все маршруты `status/start/answer/finish` используют её; внутренние сводки и таблица базы сохраняют числа для организаторов. В рабочий ответ подключена написанная пользователем `tarhan_participant_test_summary()`, но весь её массив наружу не передаётся.

Серверное разрешение пересдачи после успеха пока сохранено до прямого уточнения заказчика; скрыта именно кнопка успешного экрана. Включительная граница 25/50 также сохранена по прежнему согласованию. Выражение заказчика «более 50» нужно перепроверить для ровно 50%.

Проверки обновления: PHP/JS-синтаксис и сборка Vite прошли. Обновлённый `tests/verify-attempts.php` проверяет отсутствие `score`, `percent`, `correct` в публичных результатах и ответе REST, одновременно проверяя сохранение внутренних баллов через чтение БД. Все 10 групп проверок прошли, временные записи откатились. Повторная визуальная проверка браузера недоступна из-за отсутствия соединения с инструментом управления браузером; это не выдаётся за пройденную UI-проверку. ### Правила и поведение

- 50 случайных корректных опубликованных вопросов без повторов; один правильный вариант, 1 балл за ответ. Для запуска требуется не меньше 50 пригодных вопросов.
- 40 минут, максимум 3 попытки. Серверное правило пересдачи после успеха пока сохранено; на успешном экране она не предлагается (см. новое уточнение выше).
- Ответ сохраняется на сервере при выборе. Интерфейс подтверждает сохранение; при сбое восстанавливает последнее подтверждённое состояние и показывает ошибку.
- Обновление страницы возвращает ту же попытку, набор заданий и сохранённые ответы.
- Правильные ответы остаются на сервере; процент и балл вычисляет и хранит сервер. Участник получает только статус прохождения.
- Учитывается последняя завершённая попытка, включая результат хуже предыдущего. От 25/50 включительно сервер возвращает допуск к эссе.
- Серверный срок не зависит от часов компьютера. Клиент отображает время по серверным данным и монотонному таймеру, обновляет состояние при возвращении на вкладку и периодически во время теста.
- Просроченная попытка закрывается на сервере при следующем обращении; открытая страница запрашивает результат при истечении времени. Без открытой страницы отдельной фоновой задачи завершения пока нет. Поздние ответы не принимаются.
- Повторный старт/завершение не расходуют лишнюю попытку. Незавершённая попытка возобновляется.
- Организатор разрешает новые старты в «Тестирование». При закрытии начатые попытки заканчиваются в пределах своего срока — это поведение описано в админке и может быть изменено при новом решении организаторов.
- Приём эссе пока не подключён: на результате показывается допуск, переход к сдаче остаётся недоступным.
- Реальная регистрация и пользовательские страницы входа относятся к следующему этапу. Сейчас вход доступен штатной формой WordPress для существующих учётных записей.

### Общая таблица организаторов — уточнение 18 октября

## Ограничения
Пять вопросов — только заглушки для проверки навигации. Реальное количество вопросов не согласовано.
Нет правильных ответов, расчёта баллов, сети, создания настоящих попыток и отправки работ.
Кнопки «Пример: 60%» / «Пример: 40%» лишь переключают представление результата.
Демо-попытки и выбранные варианты хранятся только в памяти страницы; перезагрузка сбрасывает их.
Кнопка эссе показывает объяснение, а не открывает защищённое задание.
Скрытие кнопки в JS не является проверкой допуска.

## Подтверждённые правила будущего серверного теста
- 40 минут на попытку, максимум 3 попытки.
- Повторная попытка разрешена и после успешного прохождения.
- Учитывается последний завершённый результат.
- Допуск к эссе при 50% и выше; последний результат ниже 50% убирает допуск.
- Завершение при истечении времени, без показа правильных ответов.
- Организаторы вручную открывают/закрывают задания.
- Эссе: одна тема, ввод текста либо PDF/DOC/DOCX/TXT. Лимиты ещё не согласованы.
- Подтверждение передачи работ экспертам показывается на сайте после эссе.
- Отправка писем о регистрации и тесте ещё требует уточнения.
