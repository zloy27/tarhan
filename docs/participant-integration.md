**Последнее изменение:** пользователь выбрал локальный справочник «регион → населённый пункт» и ручные улицу/дом. Это реализовано и проверено; регистрация больше не ждёт ключа DaData. Текущий контракт и ограничения: `docs/geography-integration.md`.

## Реализовано и установлено локально

Рабочий WordPress: `http://tarhan-wp.local/`. Страницы `/registration/`, `/entrance/`, `/forgot-password/`, `/reset-password/`, `/essay/` используют `page-participant.php`; исходная форма регистрации и оформление сохранены. Кнопка успешного теста ведёт на `/essay/`. Верхняя панель WordPress скрыта для участников.

Код плагина разделён на модули:

- `tarhan-participant.php`: защита гостевых форм, ограничение частоты запросов, проверка и непубличное хранение файлов, скачивание с проверкой владельца/организатора.
- `tarhan-auth.php`: регистрация, адресный серверный маршрут, вход/выход, восстановление пароля.
- `tarhan-essay.php`: серверный допуск, отправка и чтение эссе, настройки и просмотр работ организатором.
- `tarhan-eassay.php`: исходная функция пользователя для текста, сохранённая без переписывания.

Новая функция `tarhan_validate_essay_file_info()` написана помощником по прямой просьбе выполнить оба этапа. Она дополняет проверку фактического содержимого файлов, но сама не доказывает формат.

## Регистрация и адреса

### Требование пользователя к общей таблице организаторов

Пользователь отдельно напомнил: общая таблица должна включать данные регистрационной анкеты по источнику https://tarhan-history.ru/tarhan-reg/, а не только ФИО, тест и эссе. Перед окончательным утверждением состава сверить исходную страницу; 21 октября повторная проверка через веб-инструмент завершилась тайм-аутом, через браузер — ошибкой срока сертификата. Полнота соответствия оригиналу пока не подтверждена.

В текущей форме проекта уже есть следующие данные, которые нужно включить в строку участника и общую выгрузку: имя, фамилия, отчество; дата рождения; личный телефон; email; регион, район/округ, населённый пункт, улица, дом и необязательная квартира; организационная форма, тип и номер учебного заведения, класс/категория; имя, фамилия, отчество и телефон представителя; состояние и защищённая ссылка подписанного согласия, факт и дата ознакомления с положением. К ним присоединяются результаты теста и эссе по `user_id`. Пароль и подтверждение пароля не являются колонками таблицы или выгрузки. Недостающие по оригиналу поля после сверки добавлять согласованно в форму, серверную проверку/хранение и таблицу.

Сервер повторно проверяет ФИО, обязательные поля, телефоны, существующую дату рождения, email, значения школы/категории из формы, пароль и согласие с положением. Пароль минимум 8 символов, подтверждение обязательно. Создаётся только роль `subscriber`; поля запроса не могут назначить другую роль. Пароли хеширует WordPress, в анкете и журналах они не сохраняются.

Анкета хранится в `wp_usermeta`, ключ `tarhan_profile`, связь с аккаунтом по `user_id`. Там же сохраняются серверно подтверждённые адресные составляющие, дата принятия положения, дата регистрации. Файл согласия — отдельное закрытое метаполе `tarhan_consent_file`.

Для несовершеннолетнего подписанное согласие обязательно; для взрослого необязательно. PDF/JPG/PNG до 10 МиБ проверяются на сервере. Квартира необязательна. Номер/тип школы проверяется по допустимому формату существующей формы; **проверки существования школы по реестру ещё нет**. Это ограничение прежнего конструктора сохранено и не выдаётся за реестр.

Маршруты `POST /wp-json/tarhan/v1/address` и `/register` реализованы. Подсказки получаются через DaData. При регистрации сервер заново запрашивает адрес через `findById` и сверяет `house_fias_id`; переданные клиентом подписи региона/улицы не считаются подтверждением. Секрет не попадает в HTML или JS.

**Ключа DaData нет**, но по последующему выбору пользователя новая форма использует локальный справочник и регистрация работает без ключа. Прежний режим полного адреса остаётся доступным только с настроенным провайдером; если он понадобится, ключ задаётся в WordPress → Тестирование → Эссе и регистрация → Новый ключ или константой `TARHAN_DADATA_KEY`. Настоящая DaData по-прежнему не проверена. В прежних тестах только внешний провайдер подменялся техническим ответом; в установленном коде тестовой подмены нет.

Оригинальная страница `https://tarhan-history.ru/tarhan-reg/` при проверке 21 октября не ответила. Поля сохранены из актуальной формы проекта; новая сверка с оригиналом не заявляется.

## Авторизация

- `POST /auth/login`: email и пароль, вход через `wp_signon()`, сессионная cookie WordPress, переход на тест.
- `POST /auth/logout`: нужен действующий пользователь и REST nonce; сессия завершается через `wp_logout()`.
- `POST /auth/forgot`: штатное создание ключа и письмо WordPress. Одинаковый публичный ответ для неизвестной почты и существующего аккаунта.
- `POST /auth/reset`: проверка ключа, новый пароль с подтверждением, завершение всех сессий. Использованный/устаревший ключ не принимается.

Письмо содержит ссылку на `/reset-password/?key=...&login=...`. Страница запрещает передачу referrer, не кешируется и убирает ключ из адресной строки после чтения. После обновления этой страницы нужно снова открыть исходную ссылку из письма. Внешняя доставка писем на целевом хостинге **не проверена**; при тестах письмо перехватывалось без внешней отправки.

Гостевые операции требуют токен, связанный с случайной HttpOnly/SameSite cookie браузера, проверяется Origin. Одного общего гостевого nonce нет. Для операций вошедшего пользователя применяется REST nonce WordPress. Ограничение частоты учитывает адрес веб-сервера, не доверяет произвольному `X-Forwarded-For`; на хостинге с прокси нужно корректно настроить реальный IP на уровне веб-сервера. Лимиты также могут затрагивать пользователей за одним общим IP.

## Эссе

Отдельная таблица `wp_tarhan_essays`: `user_id` (уникальный), `text`, `file` (закрытые метаданные JSON), `submitted_at`. Организаторская сводная таблица со всей анкетой и тестом остаётся следующим отдельным этапом.

`GET /essay/status` читает только собственную работу. `POST /essay/submit` повторно проверяет последнюю завершённую попытку, открытие приёма, лимиты, текст/файл. Проходная граница прежняя — 25/50 включительно; баллы/проценты участнику не возвращаются. Поле чужого `user_id` в запросе не определяет владельца.

Участник выбирает **текст или файл** PDF/DOC/DOCX/TXT; два способа одновременно не принимаются. TXT — UTF-8. Проверяются реальные байты, размер, расширение, MIME/сигнатуры; DOCX дополнительно проверяется как пакет Word без VBA, с ограничением размера читаемых частей. Это проверка формата, не антивирусное сканирование документов.

Отправка окончательная, без замены и черновиков. Это явно сообщается до отправки; требуется отдельное подтверждение в форме. На сервере один `user_id` — одна работа, повторные/одновременные отправки не создают дубли и не перезаписывают её. После сетевого сбоя интерфейс перечитывает состояние с сервера. Ранее сохранённая работа не удаляется при ухудшении результата пересдачи; дальнейшие правила замены/пересдач нужно согласовать.

Настройки: WordPress → Тестирование → Эссе и регистрация. Организатор задаёт тему, лимит символов, байтов и открывает приём. До заполнения этих значений приём закрыт; **за заказчика окончательные значения не назначались**. Технические верхние ограничения: миллион символов и 10 МиБ. PHP `upload_max_filesize`, `post_max_size` и лимит тела запроса веб-сервера должны разрешать согласованный объём с учётом multipart.

## Файлы и доступ организатора

Файлы не добавляются в публичную медиатеку. По умолчанию каталог расположен рядом с публичной папкой WordPress: локально `C:/Users/zloy27/Local Sites/tarhan-wp/app/tarhan-private`. Можно задать абсолютный `TARHAN_PRIVATE_DIR`. Если путь оказывается внутри WordPress или document root, загрузка отклоняется.

Имена на диске случайные; оригинальное имя используется только в интерфейсе/скачивании. Скачивание через `admin-post.php?action=tarhan_private_file` проверяет cookie, nonce и владельца либо `manage_options`, возвращает attachment + nosniff. Публичного URL на файл нет. Каталог необходимо включить в резервное копирование вместе с БД и конфигурацией.

В админке «Эссе и регистрация» есть просмотр полученных текстов, скачивание эссе/согласия и постраничная выдача по 50 работ. Это минимальный приём работ, ещё не общая таблица всех участников и не рассылка экспертам.

## Сборка, установка и проверки

Сборка: `node node_modules/vite/bin/vite.js build --outDir .participant-build --base=./ --manifest`. Новый каталог темы `participant-dist` используется отдельно от старого `dist`: старые хешированные ресурсы темы не заменяются. Обе страницы пароля используют общий Vite chunk `password`; выбор этой записи учтён в enqueue.

`tests/deploy-local-participants.ps1` сохраняет копию темы/плагина, копирует новые модули и сборку, запускает прежние проверки теста и устанавливает недостающие страницы/схему. Только локальная установка, не удалённый деплой. Перед повторным использованием сверить живые пользовательские правки с исходниками.

Исправление запуска 21 октября: сервисами управляет только приложение Local. Скрипты больше не запускают отдельные mysqld/PHP/nginx и не привязываются к порту 10005. `tests/local-runtime.ps1` читает текущие порт MySQL и версию PHP из конфигурации Local, требует запущенный сайт. Для PHP-проверок: `./tests/invoke-local-php.ps1 -Script ./tests/verify-participants.php` (аналогично для других проверок, аргументы setup/cleanup передаются после имени скрипта). Самостоятельный запуск сервисов ранее оставил MySQL на старом порту и мешал Local открыть те же файлы базы на новом. Сохранена SQL-копия, старый сервер остановлен через mysqladmin shutdown, сайт запущен штатной операцией Local; действующий порт после восстановления — 10012, но его нельзя считать постоянным.

Проверки 21 октября:

- PHP/JS синтаксис и сборка Vite.
- Все 10 групп `verify-attempts.php`: прежние тесты, баллы только внутри, предел попыток и время сохранены.
- `verify-participants.php`: токен/Origin, поля/роль/хеш пароля, создание аккаунта и дубль, согласие несовершеннолетнего, вход, восстановление и одноразовый ключ, допуск и текст эссе, повторная отправка и изоляция. Внешний адресный провайдер и отправка письма заменены только тестовыми обработчиками; данные откатываются транзакцией.
- `verify-participant-http.py`: настоящие HTTP cookie, multipart, принятие TXT и DOCX, отклонение поддельных/пустых/больших файлов, защищённое скачивание, чужая/гостевая сессия, сохранение текста, отсутствие допуска, выход. Проверяется также наличие JS/CSS обеих страниц пароля.
- Браузер: вход временного подписчика → успешный тест без числовой оценки → сохранённое эссе → выход; регистрация честно показывает отсутствие справочника; восстановление и страница без ключа открываются с оформлением и правильными состояниями.

Временные HTTP-участники создаются `participant-fixtures.php setup`; обязательная очистка `cleanup` удаляет только помеченные аккаунты/работы/файлы и возвращает прежние настройки. Скрипты проверок не размещать на публичном сервере.
