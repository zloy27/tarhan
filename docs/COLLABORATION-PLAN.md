## 1. Предварительная проверка сведений о файле — следующий самостоятельный шаг

Пользователь пишет функцию `tarhan_validate_essay_file_info($filename, $size_bytes, $allowed_extensions, $max_bytes)` в своём модуле эссе.

Вход: имя файла, размер в байтах, список разрешённых расширений без точки, положительный лимит в байтах. Аргументы считаем уже полученными в ожидаемых типах: имя — строка, размеры — целые числа. Проверку структуры HTTP-запроса и кодов ошибки загрузки выполняет серверный обработчик на этапе интеграции.

Результат функции: массив `extension` (расширение в нижнем регистре), `size_bytes` (размер), `error` (сообщение либо null). Нужно извлечь расширение, принять его в любом регистре, отклонить отсутствие/неразрешённое расширение, пустой файл и превышение лимита; размер ровно на границе допустим.

Новые инструменты объяснить перед выполнением: `pathinfo()` с `PATHINFO_EXTENSION`, `strtolower()`, `in_array()` с точным сравнением. Максимальный размер не выбирать за заказчика: передавать параметром. Согласованные форматы — PDF, DOC, DOCX, TXT.

Условие завершения: проверены допустимый файл, верхний регистр расширения, отсутствие расширения, двойное расширение вроде `work.pdf.exe`, пустой файл, превышение и точная граница размера. Это проверка сведений, а не подтверждение фактического формата содержимого. Серверная интеграция дополнительно проверяет реальные загруженные данные, MIME/формат, права и хранение.

## 2. Приём эссе в WordPress — вместе

Вместе разбираем путь данных: запрос формы → проверка входа и допуска → выбор способа сдачи → вызов функций пользователя → сохранение → ответ. Пользователь пишет посильные самостоятельные серверные функции. Перед каждой задачей объяснять новые функции WordPress в целом, их аргументы, возвращаемое значение и роль здесь.

Хуки, REST-обработчики, nonce, связь с user_id и работу с базой разбирать по одному участку. Сложные участки помощник реализует с объяснением в рамках поручения; не выдавать сразу большой готовый файл вместо совместной работы. Реальную тему и окончательные лимиты не придумывать.

Условие завершения учебного шага: пользователь понимает, какие данные получает его функция и куда возвращается результат; помощник проверил как обычные, так и пограничные случаи.

## 3. Форма, JavaScript и SCSS — помощник

Помощник создаёт HTML/SCSS-компонент в существующем стиле: одна тема, выбор «Написать текст» / «Загрузить файл», поля, ошибки, кнопка отправки, подтверждение и адаптив. Помощник пишет весь JavaScript: переключение способа, счётчик, запросы, состояния ожидания и обработку ответа сервера.

Не назначать пользователю задачи по JavaScript, SCSS, оформлению или вёрстке как обязательные учебные шаги. Клиент использует договорённый серверный формат, значения неактивного способа не мешают выбранному, сообщение об успехе появляется только после подтверждённого сохранения.

Условие завершения: интерфейс соответствует текущим требованиям и работает с настоящим обработчиком. Временные тема/лимиты в макете явно обозначены и не выдаются за решение заказчика.

## 4. Настоящая сдача и сохранение — WordPress вместе, сложная интеграция помощником

Вместе подключаем написанные функции к WordPress понятными этапами: вход и допуск после теста, одна тема, проверка запроса и повторная валидация, сохранение с привязкой к user_id, подтверждение после сохранения. Помощник берёт сложное безопасное непубличное хранение файлов и соединение с интерфейсом. Реальные вопросы, тему и лимиты получает пользователь от заказчика.

Проверить прямой доступ без допуска, чужую работу, неверный файл, повторную отправку, ошибку соединения и получение сохранённой работы организатором. Не вводить молча правила редактирования/замены/черновиков, которые заказчик ещё не согласовал.

Условие завершения: временный обычный участник проходит путь тест → эссе → подтверждение; работа доступна только уполномоченному организатору. Кнопка успешного теста получает реальный защищённый адрес эссе.

Серверные обработчики уже свёрстанных форм, WordPress-пароли, согласованные справочники и необходимые письма разбираем и подключаем вместе. Помощник выполняет сложную интеграцию и весь фронтенд; пользователь пишет посильную серверную логику и проверяет сценарии. Остальные страницы переносятся по существующему плану.

До сдачи: полный проход обычным участником на целевом хостинге, права организатора, мобильный интерфейс, восстановление пароля, корректные ссылки, резервная копия и инструкция. Отсутствующие материалы/решения фиксировать явно.

## Решения заказчика, которые нужны отдельно от учебных задач

- Одна реальная тема эссе, предел длины текста и размер файла.
- Разрешены ли замена работы и черновик, что происходит после сдачи.
- Запрещать ли повторный старт теста на сервере после успеха; сейчас кнопка скрыта, прежнее серверное разрешение сохранено.
- Порог ровно 50%: пока сохранено прежнее включительное правило 25/50.
- Реальные вопросы и ответы, необходимость писем, окончательное решение по адресам и учреждениям, данные для развёртывания.

## Правило одного учебного шага

Для каждого нового серверного шага сначала давать назначение, точные входные данные, ожидаемый результат, пограничные случаи и объяснение незнакомых функций. Затем пользователь пишет сам; помощник читает фактический файл, проверяет, объясняет ошибки и не переписывает решение целиком без просьбы. WordPress изучаем вместе. Интеграцию с большим существующим кодом не назначать пользователю как основной учебный шаг. JavaScript и SCSS полностью на помощнике.
