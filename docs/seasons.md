# Управление сезонами

В WordPress: **Тестирование → Сезоны** (`admin.php?page=tarhan-seasons`).

1. Создать сезон с согласованным названием, например `2026–2027`.
2. Выбрать его текущим, отметить открытие регистрации при необходимости и сохранить.
3. Для закрытия снять отметку и сохранить. Без выбранного сезона регистрация закрыта.

Пока настройки текущего сезона ни разу не сохранены, действует прежний режим регистрации. Создание сезона само по себе ничего не переключает. При установке модуль не создаёт сезоны и не переносит существующие анкеты автоматически.

Настройки хранятся одной записью `tarhan_seasons` в WordPress options. Сезон имеет постоянный UUID и название. На сервере проверяются права администратора, nonce, версия формы, существование сезона и уникальность названия. Сохранение настроек и окончательное создание аккаунта используют общий MySQL lock: закрытие или переключение сезона не может пройти между финальной проверкой и сохранением анкеты.

Новая анкета сохраняет `season_id` и `season_name` в `tarhan_profile`. Год участия остаётся календарным годом регистрации. Форма показывает сезон и отправляет его ID; сервер отклоняет устаревшую форму после переключения. При закрытой регистрации показывается сообщение вместо формы, API также отклоняет регистрацию. Вход в существующий аккаунт остаётся доступным.

Повторное участие подключено. После входа с прежней почтой и паролем участник без анкеты текущего сезона направляется на регистрацию. Пароль повторно не задаётся, email берётся из авторизованного аккаунта. Анкета заполняется заново, согласие загружается заново при необходимости. Один аккаунт может иметь только одну анкету в каждом сезоне.

Таблицы `tarhan_enrollments`, `tarhan_season_attempts`, `tarhan_season_essays` хранят отдельные записи по `(user_id, season_id)`. В новом сезоне доступны три попытки с нумерацией от 1. Доступ к тесту и эссе требует анкеты текущего сезона. Запросы из старых вкладок проверяются по сезону; ID попытки другого сезона не принимается. Закрытие регистрации не закрывает вход и работу уже зарегистрированных участников; приём тестов и эссе управляется прежними настройками.

Таблица организаторов и Excel показывают одну строку на участие в сезоне. Есть фильтр сезона; ссылки на карточки и документы содержат сезон, поэтому переключение текущего сезона не меняет содержимое старой карточки. Файлы доступны только их владельцу или администратору.

Миграция `tests/migrate-local-enrollments.php` сначала сохраняет резервную копию анкет, попыток, эссе и сезонов вне публичного каталога. Затем копирует старые данные в новые таблицы без удаления исходных таблиц и usermeta, проверяя совпадение перенесённых попыток и эссе. Если у анкеты уже был `season_id`, он сохраняется. Более ранние записи отображаются как **«До настройки сезонов»**: автоматически приписывать им произвольный новый сезон нельзя. Календарный год регистрации сохраняется отдельно от названия сезона.

Переключение текущего сезона скрывает предыдущий сезон от новых действий участника, но не удаляет историю. Для возврата к прежнему сезону организатор может снова выбрать его текущим.

После 25/50 или выше в текущем сезоне новые попытки блокируются, участник автоматически переходит к эссе. При повторном участии в другом сезоне снова доступны три попытки. Закрытие оставшихся попыток после успеха не меняет фактическое число уже начатых попыток в отчёте.

Проверка: `tests/invoke-local-php.ps1 -Script tests/verify-seasons.php` на работающем Local. Временные настройки и участники проверяются в транзакции и откатываются.

Полный сценарий: `tests/invoke-local-php.ps1 -Script tests/verify-season-renewal.php`. Он проверяет три неудачные попытки, повторную анкету без смены аккаунта, новые попытки, успешный тест и эссе, изоляцию сезонов, возврат к прежнему сезону и выгрузку. Все фиктивные анкеты, вопросы, попытки и настройки откатываются.
